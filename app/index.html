How the data gets here

Meridian holds a read-only token, never a credential. The handoff happens inside Plaid Link, on Plaid's own origin.

Credentials never reach us

Plaid Link runs in its own sandboxed frame. You authenticate with your bank; we receive a public token and exchange it server-side for a read-only access token. No password ever crosses Meridian.

Read-only by construction

Tokens are scoped to transactions, auth, liabilities, investments. No payment scope is requested, so money movement is not technically possible.

Webhook-driven freshness

Balances refresh on Plaid's DEFAULT_UPDATE webhook rather than polling. A stale or re-auth-required item shows its own state instead of quietly serving old numbers.

Yours to revoke

Unlinking an institution fires /item/remove, invalidates the token at Plaid, and purges the derived transaction rows. Export everything as CSV or JSON first.

About this build. The interface is complete and the arithmetic is real — compounding, amortisation, pace projection and promo countdowns all compute live from the controls. Account data is a resident fixture, because a published page cannot reach an external host. The link flow calls a mock adapter that mirrors Plaid's real signatures (/link/token/create → onSuccess(public_token) → /item/public_token/exchange), so pointing it at the live SDK is a one-file swap.
